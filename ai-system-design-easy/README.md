# 비개발자를 위한 AI 시스템 설계 입문서

> AI 모델을 직접 만들진 않지만, AI를 연결해서 **쓸 만한 서비스**를 만들고 싶은 분들을 위한 쉬운 해설 시리즈

[AI System Design Guide](https://github.com/ombharatiya/ai-system-design-guide)의 주제를 바탕으로, 웹 기획자·디자이너·비전공 학습자·AI 활용 개발자가 실무에서 바로 판단할 수 있게 새로 풀어 쓴 한국어 해설이에요. 원문을 옮긴 번역본은 아니고, 장마다 **"지금 내가 어디까지 알면 될까?"**를 기준으로 내용을 골랐어요.

## 이런 분께 맞아요

- AI API를 붙인 웹사이트나 서비스를 만들고 있거나 만들 계획인 분
- 개발자와 AI 기능을 기획·협의해야 하는 웹 기획자·디자이너
- 토큰, RAG, 에이전트, MCP 같은 말은 자주 듣는데 서로 어떻게 연결되는지 헷갈리는 분
- AI 활용 수업을 준비하는 강사

수식이나 코드를 몰라도 읽을 수 있어요. 장마다 실제 서비스 예시, 15~20분짜리 수업 실습, 스스로 확인하는 질문이 들어 있어요.

## 읽는 순서

**처음부터 차례대로** 읽는 걸 추천해요. 앞 장에서 나온 개념을 뒤에서 계속 다시 쓰거든요.

시간이 없다면 목적에 맞게 골라 읽어도 돼요.

- **AI 기능을 처음 기획한다면:** 00 → 02 → 05
- **문서 검색·챗봇을 만든다면:** 01 → 02 → 03 → 05
- **자동화·에이전트를 붙인다면:** 04 → 06 → 09
- **운영비와 속도가 걱정이라면:** 01 → 07 → 08

## 이 시리즈의 공통 원칙

- **원리는 쉽게, 판단 기준은 분명하게** → 수식보다 "내 서비스에서 뭘 확인해야 하나"부터 다루기
- **AI가 할 일과 코드·사람이 할 일 나누기** → 계산·권한·검증은 AI 말이 아니라 시스템이 책임지기
- **실제 서비스로 생각하기** → 찐망고 사주풀이, 찐망고 레퍼런스, 수업 평가표 같은 구체적인 예시 쓰기 (서비스 사례는 개념 설명용 설계 예시이고, 실제 구현 상태를 뜻하진 않아요)
- **숫자는 고정하지 않기!** → 모델 이름과 요금은 계속 바뀌니까 가상 단가로 계산 습관만 익히고, 실제 값은 공식 문서에서 확인하기
